# 时间轴标尺：字幕句与拍号

## 这一版验的是什么

标尺第二行是字幕句，点一句就能看到这句落在第几拍。字幕和 BGM 卡点必须在同一条片子里同时存在，
否则这个位置永远是空的，所以专门渲了一条两者都在的 30 秒竖屏片。

## 片子怎么来的

- 项目 `6adc2161656a13996166bbfc`，run `6ae2167c99092e973cd678fd`，时间轴引擎一次渲染成功。
- 规格是显式时间轴：10 段每段 3 秒（`seg-a/b/c` 循环），10 句字幕首尾相接，BGM 52 个拍点（103.36 BPM，首拍 0.36 秒），
  每段在拍点上打推镜关键帧，共 98 个关键帧。
- 成片 30.00 秒、1080×1920、30fps，按项目/月/时间入库到 `library/studio/2026-10/…__r1.mp4`。

## 界面核对

`beat-ruler-click.json` 是浏览器里真实点击的结果（截图 `beat-ruler-ui.png`）：

- 表头：30 秒 / 103 BPM / 52 个卡点 / 98 个关键帧。
- 第 2 句（3.12 秒）→ 第 6 拍（3.2625 秒）。
- 第 5 句（12.12 秒）→ 第 22 拍（12.556 秒）。
- 第 8 句（21.12 秒）→ 第 37 拍（21.16 秒）。

三处都对得上「第一个不早于本句起点的拍」，是真实数据算出来的，不是写死的。

## 体检误报已修

第一版成片体检报了 `text_gap`：「3.0s 起卡面没字（30% 的帧）」。原因是体检的文字取样区按竖屏卡面版式定死在画面中段，
字幕贴底时那块区域本来就没字；句与句之间的留白也被算成了缺陷。

改法：规格里有字幕行就用行的 y 与字号算取样带，并且只在各句自己的时间段内查。同一条规格重渲一次，
体检从 1 条告警变成 0 条（`findings: []`），md5 与上一版一致（渲染可复现）。卡面版式没有字幕行，仍旧走原取样框，判据不变。
