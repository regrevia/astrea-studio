# 口型范式：让嘴对上「说的是哪个字」

这条片子的口型问题不是「嘴不动」，是**嘴一直在动，但和张嘴的时机、和说的是哪个字都没关系**。
现在的做法是「音量包络 → 四档开合」（`integrations/mac-worker/export/vertical_short.py:505`
`_energy_states`、`:662` `_audio_beats`，0.1 秒一格），它只回答「这一格声音大不大」，
不回答「这一格在发什么音」。结果有两种必然：

- **说错字**：中文里 `i` 是扁嘴、`u` 是圆嘴、`a` 是大张口、`m/b/p` 是闭唇重建。
  音量四档里这四种只有开合大小不同，嘴形全一样 —— 观众看到的是「一张嘴在扇动」，
  不是「在说这句话」。
- **对不上**：0.1 秒的格子比字长得多。中文一个字 180–260ms，音量谷和音素边界不是一回事，
  嘴比声音平均早半格（50ms）起，闭口又拖到下一个字。

本文件定义固定范式：**八档口型 + 逐字时间 + 协同发音 + 可测量的验收线**。
范式只约束「这一格画哪个嘴」，不约束画法（`integrations/mac-worker/mouth_art.py` 是其中一种实现）。

## 1. 判据：先有尺子，再谈像不像

一切结论都必须由 `integrations/mac-worker/tools/lipsync_qa.py` 量出来，不靠「看着像」。
工具量的是**互相关峰值的延迟**（嘴 vs 声音），正 = 嘴早于声音，负 = 嘴晚于声音。

| 指标 | 门槛 | 含义 |
|---|---|---|
| 对齐延迟 `|lag|` | **≤ 60ms 可用，≤ 30ms 好** | 超过 60ms 人眼读作「配音对不上」 |
| 静音误开率 | **≤ 5%** | ≥120ms 静音段内（10ms RMS / 峰值 −40dBFS）嘴不该张，详见 §1.1 |
| 每 100ms 换档次数 | **≤ 1.25**（派生根） | 均值超过它说明驻留已是 50–80ms 级，读作「嘴在抖」 |
| 最短驻留 | **≥ 80ms**（派生根，理想 90–100ms） | 短于它观众读到的不是「一个字」，是「抽了一下」 |
| 全长漂移 | **≤ 60ms**（派生根，与延迟同一把尺） | 恒定偏移可以整体推一帧修；逐段增长的漂移只能返工 |

标注为「派生根」的三项是由「嘴对得上语音」推出来的可执行门槛，不是用户原话；
前两项（延迟、静音误开）是验收口径本身，**不许放宽**。工具退出码：
`0` 过、`1` 有项不过、`2` 输入有问题；`--no-strict` 恒返回 0（只用在出报告场景）。

**分段延迟极差只统计有声窗。** 每 2s 一个 4s 窗，窗内音量高于「静音线」的时间占比
`active < 0.5` 的窗一律不计（工具报 `skipped/total`）。原因：几乎全静的窗里嘴和音量
都没有可对齐的起伏，互相关峰落到哪儿全看噪声——f44 片尾窗报 **−220ms**，正是
「片尾 2s 静音 + 前一句 1s 有声」这种窗口，和真实漂移毫无关系，却足以把极差抬到 260ms。
改这个口径不是放宽：人造病灶验证过（`/tmp/qaR44/drift_sim.py`／`spanfix.py`）——
真恒定偏移（±120ms）极差只有 40–70ms、真渐进漂移（4%）极差 225ms，过滤后仍报 225ms，
该抓的照样抓。

### 1.1 第四把尺：开头不早开（静音必闭口，f36 实测）

单看整体延迟会漏掉一整类问题。f36（`~/CreatorStudio/deliver/envoy-f36.mp4`）成片实测：
整体延迟 **+20ms**、r=**+0.61**；逐场用音频级复核 0~15ms —— 数字都合格，但
**每场开头的前 0.2s 嘴已经张着**，逐场静音误开 **8.6%~17.6%**（全部越过 5% 线）。
观众读到的不是「对不上」，是「还没出声嘴先动」。这是另一把尺，不能被整体延迟代表。

| 指标 | 门槛 | 怎么算（`lipsync_qa.py --json` 字段） |
|---|---|---|
| 开场领先张开 | 最大提前 **≤ 60ms**（逐场各算，不许平均；60ms = `LOOKAHEAD_MS=20` + 一帧 50fps 协同发音预算） | 第一个有声帧往回看 200ms，`early_open.lead_ms_max` |
| 静音帧非闭 | **≤ 5%**，分母只算 **≥120ms** 的静音段 | 10ms RMS、相对峰值 −40dBFS，`silence_spec.false_open` |
| 前导非闭 | **= 0 帧** | 首字起点之前，`silence_spec.lead_frames` |
| 尾部非闭 | **= 0 帧** | 末字 + 120ms 之后，`silence_spec.tail_frames` |
| 词内塞音误闭 | **= 0 段** | 40~80ms 空隙被整段闭成 `closed` 的数量，`silence_spec.stop_misclosed` |
| 口型轨长度 | `= round(dur*50)` | 见 5.1，超长即按压帧返工 |

静音段为什么要 ≥120ms 才算：40~80ms 的词内塞音空隙（`b/p/m` 成阻）本来就该闭，
把它们算进静音分母就会出现「同一批帧既要求不许闭、又要求必须闭」的自相矛盾。
`lipsync_qa.py` 里旧口径（绝对 −45dB、25ms 窗）仍会打印，但那只是对照，不作判据。

常见成因，按出现频率排：① `lipsync` 的 20ms 预判被外层再放大成整段提前；
② 场景切换把上一场的尾音/静音段带进本场 `lip_audio`，包络起点就是高点；
③ 分句 `_say` 的停顿 gap 被算进语音段，起播点前移。
修法只有一条：**起播点由第一个有声帧定（`lipsync.py:384 _first_voiced`），不由场景起点定**；
开口档在 ≥120ms 的静音段里强制回落 `closed`（`_silence_mask` `:546` → `_enforce_silence` `:594`），
不靠 `_LIP_CLOSED` 的概率挡。**已落 `0191c84`**：`build()` 里 `_enforce_silence` 先按
轨级包络把前导、尾部（`TAIL_PAD_S=0.12`）和每个 ≥120ms 静音段钉成 `closed`，再交给 `_settle`
（`protected=` 保护这批帧），并把 `_calibrate` 的容差从 80ms 收到 40ms、`delta<0` 不再往回推。

### 1.2 音频级 vs 视频级：为什么同一个片子两组数字

| | 音频级（口型轨） | 视频级（成片代理） |
|---|---|---|
| 输入 | `--audio` + 逐场 states json | 成片画面里 36px 嘴区的红色像素质量 |
| 时间粒度 | 20ms（50fps 轨） | 33ms（30fps 取样） |
| 量到什么 | 设计意图的开口度 | 经过渲染、遮挡、光照之后的像素变化 |
| 实测 r | 0.6~0.8（带侧车 0.83） | 0.45~0.65（f32 +0.47、f36 +0.61） |
| 判定口径 | **权威**：延迟、静音必闭（前导/尾部/长静音/塞音）、换档、漂移全用 | **参考**：只认延迟 ≤60ms 与静音误开 ≤5%；r<0.30 不判失败 |

口径纪律：两组数字**不能交叉比**，也不能拿一条的 r 否定另一条。同一条片子的静音误开，
**渲染级必然 ≥ 轨级**（36px 代理的分辨率、30fps 抽帧相位、`lip_t0` 三者叠加），
差值属方法学，**不得据此判轨不合格**；判轨只看 `--audio`+`--states` 那条。视频级 r 低先怀疑代理定位
（看 `patch_r`、两半延迟差 > 60ms），再用音频级复核；音频级 r < 0.3 才是口型设计本身的问题。


### 1.3 口型轨最小可测口径（backend-timeline 给的口径，出片前自检就按这个）

1. 只测**一句一轨**：`--audio <句 mp3> --states <句 states json>`，别拿整片拼出来的轨量逐场。
2. 轨必须自报 `fps`/`t0`/`states`；长度 `= round(dur*fps)`，`drift_ms` 超过一帧就说明补帧没重映射时间。
3. 静音判据固定为 **10ms RMS、相对峰值 −40dBFS、连续 ≥120ms**；三项硬结果：前导 0 帧、尾部 0 帧、长静音段内非闭 ≤5%。
4. 塞音空隙（40~80ms）单独数：被静音规则整段闭掉即为误闭，目标 0 段。
5. 延迟用互相关峰，`|lag| ≤ 60ms` 过、`≤ 30ms` 好档；`r` 只作陪衬（`< 0.30` 打 ⚠ 不判失败）。
6. 所有门槛**逐场各算**，禁止用整片平均掩盖某一场的开场早开。

三处实现事实（别改回去）：

- `lipsync._enforce_silence()`（`export/lipsync.py:594`，`build()` 内 `:646` 调用）：前导 / 尾部（末字 + 120ms）/ 每个 ≥120ms 静音段强制 `closed`，且在 `_settle` 之前跑、把这批帧放进 `protected`。
- `char_layer` 渲染级兜底：逐格 **−45dB** 覆盖成闭口，句尾再收 **60ms**（`integrations/mac-worker/export/char_layer.py`）；这是第二道保险，不是判据。
- `_envelope_db` 曾是 50Hz 的包络又被乘 `fps/10`，等于把静音阈值按帧率缩放（masking bug），已修；**别把 50Hz × `fps/10` 的写法加回来**。

## 2. 八档口型（正字面）

档名是出片、QA、素材命名的共同词汇。canonical 顺序见
`integrations/mac-worker/export/lipsync.py:37` `STATE_ORDER`；画法在
`integrations/mac-worker/mouth_art.py:18` `STATES`、`:264` `_draw_mouth`（旧档 `closed/half/round/open` 必须继续可用，
paper 链路和旧 spec 依赖它们）。

| 档 | 开口度 | 对应音（韵母/声母） | 画面读法 |
|---|---|---|---|
| `closed` | 0.00 | `m b p`、静音 | 唇线闭合，不露齿 |
| `teeth` | 0.80 | `s z c zh ch sh r j q x` | 微开露齿，齿宽 ≤ 0.6 倍嘴宽 |
| `narrow` | 0.40 | `i`、`ie in ing` | 横向扁、纵向窄 |
| `mid` | 0.52 | `e ei en eng` | 中性半开 |
| `round` | 0.58 | `o uo`、`ao ou` | 圆，但不收唇 |
| `pucker` | 0.62 | `u ü` | 收唇前突，比 `round` 更小更紧 |
| `wide` | 1.00 | `a ai an ang` | 上下张到最大 |
| `half` | 0.35 | 过渡档 | 只做收口过渡，不作稳态 |

`OPENNESS` 数值（工具里的排序值）只用来算相关和排序，**不参与出片**。

### 2.1 一个字要拆成两段

「一个字一个嘴」也对不上，因为中文音节是「声母段 + 韵母段」，前半和后半嘴形不同：

- 声母段（约前 40%）：`m/b/p` → `closed`；齿音类 → `teeth`；其余辅音 → 该字的韵母形但更小一号。
- 韵母段（其余）：按上表定形。

实现参考 `lipsync.py:193` `_char_mouths(ch)`（返回 `(lead, final)`）与
`:441` `_frames`（按字符时间把 `lead` 铺到前半、`final` 铺到后半，分界在中点）。
`_text_mouth(ch)`（`:183`）是无 pypinyin 时的降级：只按字面猜一次，不拆两段。

没装 `pypinyin` 也能跑，但那是降级路径：`lipsync.py` 里有韵母类降级表，不保证 `i/u/a` 分得开。
**要求多余音素区分度的片子，必须装 `pypinyin`。**

## 3. 时间来源：优先级写死，不许各段自己猜

口型长度必须等于这句配音的真实长度，且每一格对应真实时间。三条来源按可复现性排序
（`lipsync.py:431` `_timeline` 决定，`build_words` 的 meta 里 `source` 字段会写出来）：

1. **`*.words.json` sidecar（`source="words"`）** —— edge-tts 的 WordBoundary 或外部工具给的逐字表，
   同目录同名（`lipsync.py:210` `_sidecar`、`:214` `load_words`）。可复现、零重算，**首选**。
   合成时直接落盘：`lipsync.py:642` `words_json(text, audio, out)`。
2. **音频包络音节切分（`source="syllable"`）** —— `lipsync.py:329` `_syllable_timeline`：
   解码 16k 单声道 → 10ms 能量 → 找谷 → 有声段（`:289` `_spans`）→ 按字数分配 →
   `:431` 再对一次 `_first_voiced`（`:384`）。没有 sidecar 时的默认路径。
3. **按字数均分（`source="uniform"`）** —— `lipsync.py:371` `_uniform_timeline`。只在上面两条都失败时用；
   `coverage`（meta 里有）会明显偏低，这种片子只能算「能看」，不能算过验收。

覆盖率是硬信号：`build_words` 返回 `coverage = timed_seconds / duration`。
低于 0.9 说明大部分字没有真实时间，延迟指标再好也不能当通过 —— 那只是「整体偏了一点」，
逐字对不上。

### 3.1 音色通道与逐字侧车（sidecar）

侧车的生产者是配音模块，不是口型模块。三件事必须同时成立，逐字口型才有输入。

**① 音色写法与语速。** `spec.voice` 两种写法等价：`edge:zh-CN-XiaoxiaoNeural` 与裸
`zh-CN-*-Neural`（`slides_render.py:300` `_edge_voice` 认这两种前缀，正则见 `_EDGE_VOICE_RE`）。
`spec.rate` 只在 edge 分支生效：0.92 → `-8%`，夹在 ±30%（`slides_render.py:306` `_edge_rate`）；
SAMI 分支语速固定 1.0，写 `rate` 不生效，别指望用 rate 卡时长。
合成不在主进程做（系统 python3 没有 `edge_tts`）：走
`integrations/mac-worker/tools/edge_tts_once.py`（`slides_render.py:297` `EDGE_TTS_ONCE`），
由 MPT venv 的解释器跑子进程，主进程只 import `subprocess`。

**② 缓存键与命中条件。** 键 = `voice + rate + 原文`（`slides_render.py:287` `_tts_cache`，sha1 前 20 位）。
命中要求 **mp3 和 `<stem>.words.json` 都在**（`_edge_tts`，`:327`）：只剩 mp3 时**删缓存重合成**，
绝不静默退回包络猜口型。淘汰时两个文件一起删（`prune_tts_cache`，`:253`）。
同理：改了稿子一个字就重合成，没改就零网络复用。

**③ 多段配音的侧车必须重拼。** 一屏台词是逐句合成再 concat 的（`export/vertical_short.py:833` `_say`）：
每句各自的 WordBoundary 时间只在它自己的 mp3 里，拼成一条后必须重算 ——
`_retime(chars, tempo, offset)`（`:821`）= 「atempo 时长倒数缩放 × 段偏移累加」，
偏移是前面所有「句子时长 + 停顿」的累加（`_mp3_dur` `:784` + gap）。gag 拉慢走 atempo
（0.95/0.86，`_gag_tempo` `:757` / `_slow` `:770`），时间同样按倒数换算。
**某一段缺侧车就整条不写**（在写盘之前 `return`）—— 半截时间表比没有更糟，口型会一路跑偏。
拼好写到成片 mp3 的 sidecar（`_write_chars` `:813`），口型模块只认这个路径（`lipsync.py:210` `_sidecar`）。

**默认音色结论：`edge:zh-CN-XiaoxiaoNeural` + `rate=0.92`。**
唯一决定性理由是**只有它给 WordBoundary**（本轮实测覆盖 19/19 句，逐字时间可用）。
男声备选 `zh-CN-YunyangNeural`；要剪映播音腔用 `sami:BV411_streaming`，
但 SAMI 不给逐字边界 → 口型精度降级为包络推断（可看，不能当验收基线）。

侧车实际长相（`chars` 数组，`t` = 起点秒，`d` = 时长秒）：

```json
{"chars": [{"ch": "二", "t": 0.1043, "d": 0.1902},
           {"ch": "十", "t": 0.2945, "d": 0.1902}]}
```

## 4. 协同发音：早一点、久一点、开快闭慢

三条规则，都在 `lipsync.py:463` `_coarticulate` 里：

- **提前 20ms**（`:50` `LOOKAHEAD_MS`）：嘴比声音早一点点。再早会被读成「抢拍」，
  晚 40–60ms 就不像在说话 —— 这就是验收线 60ms 的来源。
- **开口方向立即生效，收口方向才驻留**：这张嘴是观众读「开口」的，延迟张嘴等于丢字；
  收口拖 1–2 格反而像真人在收。
- **最短驻留 90ms**（`:52` `MIN_DWELL_MS`）：短于它的段并进前一段（`:488` `_settle`）。
  50fps 下 4–5 格。工具侧对应的下限是 80ms（`MIN_DWELL_MS=80.0`），留 10ms 容差。

静音一律 `closed`（`:546` `_silence_mask` → `:594` `_enforce_silence`，阈值按这句自己的能量分布取，下限 0.02），
**不允许为了「嘴别停」在句间补开合** —— 那是静音误开率的主要来源。

### 5.1 曾经的致命缺陷：`_bridge` 插帧但不重映射时间（已修，别再改回去）

**曾经的形状**：`_bridge` 在直接开↔闭两端之间插 2 格中间档，轨变长，但 `_lip_mouth` 仍按
`i = int((t - t0) * 50)` 索引 → 口型轨被当 1.05x 慢放，漂移随时间累积到秒级。
实测那条片子 1677 格 vs 音频 1609 格，全长漂 +1356ms、r=+0.05、静音误开 59.6%。

**现在的样子（本范式要求保持）**：

- 文本路径（`lipsync.build`）产出的轨**长度只许等于 `round(dur*50)`**：
  `char_layer.py:266 _mouth_states_text` 末尾用 `:249 _fit_track(states, n)` 钉死（多截少补），
  不再 `_settle` / `_bridge` —— `lipsync` 内部已经做过 20ms 预判 + 90ms 最小驻留，外层重复加工只会破坏时间映射。
- `_settle` / `_bridge` **只留给老包络路径**（没有 `lip_text` 时）。
- `_lip_mouth` 索引前先自查：`len(states)` 与 `dur*50` 差 > 5% 就改用
  `rate = len(states) / dur` 索引（插件/上游又插帧时不再整体慢放）。
- `import lipsync` 包内相对导入优先（`from . import lipsync`），失败才退裸 `import`
  —— 否则工具脚本直跑时可能静默找不到模块、白退回包络四档。

改这层任何代码后，必须重跑 §6 的第 1 步：`drift` 必须 ≤ 60ms（新基线 −2ms），否则就是又插帧了。

### 7.6 塞音空隙：2 帧闭口只放宽 1 帧（f48 三腿复核，2026-10-27）

验收里「塞音空隙」是单独一项：40~80ms 的词内静音**整段闭嘴**记 `stop_misclosed`，
要求 **0 段**。30fps 下 40~80ms 只可能是 **2 帧**，而规则 3「当格 < −45dBFS 一律 `closed`」
会把 /t/ /k/ 的爆破整段闭死 —— f45a（换稿）就是这样拿了「误闭 2」。

修法落在 `char_layer.py::_relax_stop_gaps()`，三件事定死：

1. **只放宽 1 帧，不是 2 帧**。验收判「整段全闭」看的是这段里有没有**任意**一帧非 `closed`，
   放 1 帧就够；放 2 帧会把上一句尾的开口帧和新句子的开口帧连成一片，起点前凭空多出
   67ms 开口，直接撞第四把尺「开场领先 ≤60ms」（f47a 实测：误闭清 0，但 1/18 处提前 200ms）。
   挑哪一帧放：两帧里逐帧平均 dB **更低**的那帧改成 `narrow`（`_frame_db()` 同 QA 口径，
   10ms 单元、帧边界 `ceil(k*(1000/fps)/10)`）。
2. **必须在成片帧号上做，不在逐段轨上做**。逐段 `_enforce_quiet()` 看不见段位移后的帧号，
   在轨上放宽落不到验收数的那两帧上（f46a 实测：gate 逐字节没变，误闭还是 2）。
   现在 `build()` 里先 `_clamp_lip_to_audio()` 得到成片级口型，再用 `_film_frame_db()`
   按段的 `lip_t0` 折回该帧的配音 dB，`_relax_stop_gaps()` 之后再画 —— 帧编码进 webm 就改不回来。
3. **只碰长度正好 2 的闭口串**，首尾串不动，所以「≥120ms 静音必闭」一格没少
   （长静音 18 段 0 段漏，三腿都是）。

同一份代码三腿复核（脚本 `/tmp/v48.sh`，每腿新 workdir、同一套 6 镜/paper style）：

| 腿 | 变的是什么 | 全长漂移 | 塞音误闭 | 长静音漏 | 开场领先 | 判定 |
|---|---|---|---|---|---|---|
| `envoy-f48base-paper.mp4` | 原稿原声 | +11ms | 0 | 0/18 | 0/17（0ms） | **过** |
| `envoy-f48a-paper.mp4` | 换稿（`/tmp/spec45a.json`） | −5ms | 0 | 0/18 | 1/18（33ms） | **过** |
| `envoy-f48b-paper.mp4` | 换声（`edge:zh-CN-XiaoyiNeural`） | +16ms | 0 | 0/17 | 0/17（0ms） | **过** |

三条都 `video_qa.py` → `{"findings":[],"ok":true}`。**这就是「换稿/换声不回归」的实证**：
口型轨按每个角色自己的配音逐帧推，换稿、换音色、换语速，判据全部重算，不靠任何按片子写死的参数。

起音配对口径（`_onset_lags`，负=嘴晚于声）三腿中位一致在 −33ms 左右、配 38/40 处，
说明换稿换声没有把系统偏置推歪；它的绝对值受「越过 0.30 开度」这一阈值影响，
**只用腿间相对比较，不当绝对延迟读**。

## 8. 哪些做法是错的（踩过的坑，别再回来）

- **固定周期开合**（正弦 / 「每 0.4 秒张一次」）：和语音完全无关，是最典型的「嘴在扇风」。
- **只开合、不换形**（四档只按音量分大小）：`i/u/a/m` 全画成同一个椭圆 —— 这就是
  「说错字」。观众说不出哪不对，但会说「不像在说话」。
- **用音量代替音素**：音量回答「多大」，口型回答「哪个音」。两者正交，不能互推。
- **嘴晚 60ms 以上**：这是「配音对不上」的硬线；「早」比「晚」好，所以预取 20ms 是允许的、
  滞后补 40ms 不行。
- **在 24px 宽的嘴上画高光**：嘴部在成片里只有 30–40px 宽，任何高光、牙齿细节都会变成噪点。
  嘴形靠**轮廓宽度/高度比**和开口度表达，不靠内部细节。
- **句间补开合「让嘴别停」**：静音误开是第一眼出戏的原因，句间必须 `closed`。
- **逐字时间用「按字数均分」还当通过**：`coverage < 0.9` 的片子只能算能看，
  延迟指标会被均分掩盖（整体对齐、逐字全错）。
- **补过渡帧改变轨长**：见 5.1。过渡要占**已有格子的时间**，不能凭空延长轨——修过一次的坑，回归即返工。
- **拿成片代理指标当唇读结论**：成片模式量的是像素面积变化，能判「时间对不对」，
  不能判「嘴形对不对」。嘴形要用 `--states` 模式量 + 人工看 3 帧。
- **拿视频级 `r` 当失败线**：30fps 取样 + 36px 代理的 r 天花板就在 0.6，`r<0.30` 只说明
  「代理或定位不可信」，该做的是换音频级复核或重定位嘴部，不是放宽延迟。f32 就是 r 低
  且延迟真的坏，f36 是 r 正常而逐场早开 —— 两种情况必须分开处理。
- **用全片平均代替逐场**：f36 全片静音误开 4.4%（过）、逐场 8.6%~17.6%（全不过）。
  任何「每场都可能犯」的毛病（早开、句间不闭）都必须逐场报，平均数是掩盖，不是证据。
- **把「分段延迟极差」的告警当真实漂移去改口型轨**:极差是互相关在低能量窗上的
  量测假象。判断真假只需看两件事：一、该窗 `active` 是否 <0.5（全静音窗峰值无意义）；
  二、`r_peak` 与附近 30ms 内的 `r` 差多少（f44 片尾窗差 0.013，等于没有唯一峰）。
  真漂移的样子是人造 4% 渐进拉伸：极差 225ms **且** 每窗峰都很尖。三次返工都是错在
  这里，正确动作是修 QA 口径（§1 已改成只统计有声窗），不是改 `char_layer`。
- **改了音频滤镜链却只 `ffprobe -show_streams` 验收**：`loudnorm`+`atrim`+`-t` 时
  stream duration 报 33.922，解码只有 33.844。音频验收唯一算数的是「解码成 wav 再量长度」。

## 9. 落地顺序（出片前检查单）

1. 生成口型轨 → 导出 JSON → `lipsync_qa.py --audio ... --states ...`，`|lag| ≤ 60ms`、
   静音误开 ≤ 5%、**开场领先 ≤ 60ms**（第四把尺，`开场领先张开` 那行）。
2. 确认 5.1 的时间轴约束没被破坏（口型轨格数 = `round(dur*50)`、`drift ≤ 60ms`）；回归就返工，别调参糊过去。
3. 每场各跑一次口型轨模式（§6.2 的循环），**逐场静音误开都 ≤ 5%**；全片平均合格不算过。
   → 音频侧另加一条硬检查：`ffmpeg -i out.mp4 -f wav` 解码后时长必须 = 画面时长（f44 起 33.922s），
   `ffprobe` 的 stream duration 不算数。
4. 每条新片跑一次成片模式，确认两半延迟同向、极差 ≤ 60ms；`r<0.30` 只作参考，别据此放宽延迟。
5. 随机抽 3 帧人工核嘴形（`i` 扁 / `u` 圆 / `a` 大张 / `m` 闭）—— 工具量不出这个。
6. 全部通过才进成片队列；`exit 1` 的片子不进队列，不靠人工「看着还行」放行。
